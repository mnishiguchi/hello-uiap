# アーキテクチャ決定記録

`hello-uiap` で採用している開発方針を、個別の設計判断として記録します。

このリポジトリは学習用であり、公式 UIAPduino の手順をできるだけそのまま使い、
独自の仕組みは必要な範囲に限定する方針です。

## 決定マップ

| 番号 | 問い | 現在の判断 |
| --- | --- | --- |
| [0001](0001-公式uiapduinoのセットアップを既定とする.md) | UIAPduino のセットアップを何に合わせるか | 公式ドキュメントと公式 Board Manager package を既定とする |
| [0002](0002-arduino-cliを主な開発インターフェースとする.md) | Arduino 開発をどのインターフェースで行うか | Arduino CLI を主経路とし、`scripts/uiapduino` は薄いラッパーにする |
| [0003](0003-ch32v006はch32funを標準開発パスとする.md) | CH32V006 をどう開発するか | 公式 Arduino 対応までは `ch32fun` + `minichlink` を標準パスとする |

これらは現在の採用判断です。実装手順や一時的な検証結果は ADR ではなく、README、
各サンプルのドキュメント、worklog に記録します。

## ADR の書き方

ADR は4桁の連番を付け、原則として次の構成で記述します。

```markdown
# NNNN: タイトル

## 状態

採用

## 背景

## 決定

## 理由

## 影響

## 再評価条件
```

採用済みの判断を変更する場合は既存 ADR を書き換えず、新しい ADR から置き換える判断を
明記します。
