# 0003: CH32V006 は ch32fun を標準開発パスとする

## 状態

採用

## 背景

UIAPduino Pro Micro CH32V006 V1.1 は、CH32V003 と同じ Arduino 開発フローを公式には提供していない。
現時点の UIAP 公式ドキュメントでは Arduino IDE / PlatformIO は未対応であり、`ch32fun` と
`minichlink` を使う方法が案内されている。

`hello-uiap` には UIAP Arduino core にローカル定義を追加して CH32V006 を扱う実験的な経路もあるが、
これを初学者向けの既定にすると、公式手順との差分と保守対象が増える。

この判断は、V006 のサンプルで `ch32fun` path を推奨し、Arduino path を experimental として
分離している既存方針を遡及して記録する。

## 決定

CH32V006 V1.1 の標準開発パスは、公式サポート状況に合わせて `ch32fun` + `minichlink` とする。

```text
CH32V006 source
  -> ch32fun
  -> RISC-V toolchain
  -> minichlink
  -> UIAPduino CH32V006
```

Arduino core へのローカル拡張は実験用として残すが、README の happy path や初学者向け手順には
採用しない。

## 理由

- UIAP 公式ドキュメントと同じ経路を使える。
- 未サポートの Arduino integration を既定として保守せずに済む。
- V003 と V006 のサポート状況の違いを明確にできる。
- Arduino support の検証は、安定した V006 開発経路と分離して続けられる。

## 影響

- V006 の最初のサンプルは `ch32fun_projects/ch32v006_blink` とする。
- `sketches/ch32v006_blink` と `arduino_support/` は experimental として扱う。
- V003 と V006 で開発フローが異なることを README で明記する。
- V006 の Arduino support を利用する場合は、対応範囲を個別に検証する必要がある。

## 再評価条件

- UIAP が CH32V006 の Arduino IDE / Arduino CLI 対応を公式に提供した場合。
- 公式 Arduino core だけで V006 の build / upload が安定して行えるようになった場合。
- `ch32fun` 以外の公式推奨開発パスへ UIAP の方針が変更された場合。
